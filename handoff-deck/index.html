WHY · โจทย์และคำตัดสิน

ทำไมต้องมี harness และทำไมเขียนเอง

โจทย์: ให้คนหน้างานถามระบบเป็นภาษาคน แล้วได้คำตอบจากข้อมูลจริงของบริษัทตัวเอง — ไม่ใช่แชตบอตความรู้ทั่วไป และไม่ใช่ AI ที่กดบันทึกแทนคน

ทางที่พิจารณาแล้วไม่เลือก
ทางเลือกทำไมไม่เลือก
ใช้ framework เอเจนต์สำเร็จรูปคุมไม่ได้ว่าอะไรถูกส่งเข้าโมเดล · เพิ่มรั้วของเราเองไม่ได้
ให้แกนรู้จัก Beside โดยตรง (import โค้ดตัวเชื่อมเข้าโปรเซสเดียวกัน)มีระบบที่สองเมื่อไร แกนต้องแก้ทุกครั้ง · ทดสอบแยกไม่ได้
รันโมเดลในเครื่องอย่างเดียววัดแล้ว: เรียกเครื่องมือไม่เป็น/ช้า — แต่เปิดทางไว้ (สไลด์ 11)
RAG ค้นคู่มือคำถามจริงคือ “ของเหลือเท่าไร” “ใบนี้ถึงไหน” — ต้องการข้อมูลสด
ให้ AI เขียน/บันทึกเอกสารเองผิดแล้วไม่มีใครเห็น — จบที่ “เปิดจอพร้อมค่าให้คนกด” แทน (สไลด์ 21)
คำตัดสินหนึ่งบรรทัด
แกน harness = โปรแกรมทั่วไปที่ไม่รู้จัก Beside เลย
· ทางเดียวที่แกนคุยกับระบบงานคือ MCP
· ความรู้โดเมนอยู่ใน skills + resources ที่เปิดอ่านเมื่อเกี่ยว
· รั้วคือ ตารางสิทธิ์ + hook + เทสต์ ไม่ใช่ประโยคขอร้องใน prompt
หลัก 10 ข้อที่ทุกการตัดสินใจอ้างกลับมา
1 · โมเดลคือ CPU

3 · เปิดอ่านเมื่อเกี่ยว
ดัชนีอยู่ใน prompt · เนื้อหาเต็มค่อยอ่าน
4 · ตรวจสอบนอกโมเดล
hook/เทสต์ป้อนผลกลับ ไม่ถาม “แน่ใจไหม”
5 · สิทธิ์แยกจาก prompt
ตารางตัดสิน ไม่ใช่คำขอร้อง
6 · ย่อความ ไม่ตัดทิ้ง
บริบทเต็มแล้วสรุป ไม่ใช่ตัดหัวทิ้ง
7 · log ได้ replay ได้
ความลับถูกปิดบังก่อนเขียน
8 · ทำงานในนามผู้ใช้เสมอ
ตั๋วของคนที่พิมพ์ · Beside ตัดสินสิทธิ์
9 · ไม่แตะฐานของระบบปลายทาง
ใช้เฉพาะ API ที่เขาเปิด
10 · เขียนผ่านจอที่คนกด
ไม่มีเครื่องมือเขียนในตัวเชื่อม

AI 2/7 · หลักข้อ 1 ของโครงการ

โมเดลคือ CPU ไม่ใช่โปรแกรม ทั้งระบบมี loop เดียว

เราไม่ได้เขียน “ถ้าผู้ใช้ถามเรื่องสต๊อก ให้เรียกเครื่องมือ A แล้ว B” ไว้ที่ไหนเลย — เราให้เครื่องมือกับกติกา แล้วปล่อยให้โมเดลเลือกลำดับเอง วนจนกว่าจะตอบได้

สิ่งที่ loop นี้ “ไม่ทำ” โดยตั้งใจ
  • ไม่ลองใหม่ด้วย prompt ที่ต่างออกไป เมื่อโมเดลตอบไม่เข้าท่า — ผลจะไม่ซ้ำและตรวจไม่ได้
  • ไม่เดาเจตนาให้ผู้ใช้ · ถ้ากำกวมต้องถามกลับ (เครื่องมือ ask_user)
  • ไม่แก้คำตอบของโมเดล · ถ้าเลขไม่มีที่มาก็ติดป้ายเตือน ไม่ใช่ลบทิ้งเงียบ ๆ
  • ไม่ให้โมเดลตรวจงานตัวเองในข้อความเดียวกัน — ผลการตรวจต้องมาจากเทสต์/hook ที่รันจริง

MCP (Model Context Protocol) = สัญญามาตรฐานว่า “โปรแกรมที่มี AI” กับ “ตัวเชื่อมระบบงาน” จะคุยกันอย่างไร — ตัวเชื่อมประกาศว่ามีเครื่องมืออะไร รับอาร์กิวเมนต์แบบไหน อ่านหรือเขียน แล้วฝั่ง AI ก็เรียกใช้ได้โดยไม่ต้องรู้ภายใน

ต่อตัวเชื่อมด้วย config ล้วน ๆ
[[mcp_servers]]
name = "beside"
command = ".venv/bin/beside-mcp"
env = { BESIDE_USER = "${BESIDE_USER}", BESIDE_TENANT = "cmos", ... }
login = ".venv/bin/beside-mcp --login"   # ให้คอนโซลล็อกอินแทนผู้ใช้แต่ละคน

[permissions.allow]
mcp_readonly = ["beside"]      # เชื่อคำประกาศ "อ่านอย่างเดียว" ของตัวเชื่อมนี้
[permissions.deny]
mcp_tools = ["*save*", "*delete*"]   # รั้วชั้นสอง ชนะทุกอย่าง

ห้าข้อที่ห้ามหลุด ถ้าจำได้แค่หน้าเดียว ให้จำหน้านี้

1 · ทำงานในนามผู้ใช้เสมอ
ตั๋วของคนที่พิมพ์ · ระบบปลายทางเป็นคนตัดสินสิทธิ์ · 403 คือคำตอบที่ถูกต้อง ไม่ใช่ปัญหาที่ต้องหาทางอ้อม
2 · อ่านอย่างเดียว
การบันทึกเกิดในจอที่คนกด · ผู้ช่วยพาไปถึงหน้าประตูพร้อมของครบ แล้วหยุด
3 · รั้วต้องเป็นโค้ด
ตารางสิทธิ์ · hook · เทสต์ — ไม่ใช่ประโยคขอร้องใน prompt ซึ่งพลาดแล้วพลาดเงียบ
4 · ห้ามปล่อยผ่านเงียบ ๆ
ตัดข้อมูลต้องบอก · ไม่รู้ต้องบอกว่าไม่รู้ · เลขไม่มีที่มาต้องติดป้าย · เปิดจอไม่สำเร็จห้ามบอกว่าสำเร็จ
5 · วัดก่อนเชื่อ
ทุกคำว่า “เร็วขึ้น/ดีขึ้น” ต้องมีตัวเลขและไฟล์ผลกำกับ · ทุกเส้นทาง API ต้องยิงจริงก่อน ไม่มีการเดา
งานฝั่งเราพร้อมส่งต่อแล้ว — โค้ด เอกสาร ชุดวัดผล และรายการค้างครบ
